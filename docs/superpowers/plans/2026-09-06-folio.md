# Folio Implementation Plan

> Execute with superpowers:subagent-driven-development. The root implements the interface while a bounded server task runs independently.

**Goal:** Deliver a runnable personal investment application with the complete screen set, real persistence, provider boundaries, and verified calculations.
**Architecture:** React client consumes typed /api endpoints. Express protects SQLite user data and calls external providers server-side. Demo sessions exclusively use an isolated demo provider.
**Tech Stack:** React, TypeScript, Vite, Express, SQLite, Recharts, Zod, Node test runner, Playwright.
**Spec:** docs/superpowers/specs/2026-09-06-folio-design.md

## Global constraints
- No broker tokens in frontend responses or bundles.
- Demo data only in demo providers; empty live data remains empty.
- Preserve US/India native quote currencies and apply explicit FX for aggregation.
- No placing trades or moving funds.
- Every metric needs adequate inputs, provenance and an as-of date.

## Tasks
- [ ] 1. Server and providers: implement the contract in docs/backend-brief.md, schema, authentication, data APIs, imports, broker connection, provider capability status, insights and API security tests. Independent of client implementation.
- [ ] 2. Financial engine: shared/analytics.ts with tests/analytics.test.ts; verify FX conversion, weighted allocation, TWR flow neutrality, drawdown, XIRR, history reconstruction, and guards for insufficient data before wiring charts.
- [ ] 3. Client: src components, route screens, responsive design system, accessible chart controls, search, persistent watchlists, currency/theme, onboarding and imports. Consume shared/types.ts and backend contract.
- [ ] 4. Integration: run typecheck, build, tests, browser flows, desktop/mobile visual QA, and independent code review. Resolve material findings; document configuration, provider limitations, deployment and verification.
